# Output Data

## `session_counts.tsv`

Generated by `invoke run-statistics`. Long-format table with one row per (dataset, subject) pair.

Columns: `dataset`, `subject`, `n_sessions`

## `fmri_stats.tsv`

Generated by `invoke run-fmri-stats`. One row per dataset with aggregate fMRI acquisition statistics.

Columns: `dataset`, `total_runs`, `avg_runs_per_session`, `avg_run_duration_h`, `avg_session_duration_h`, `total_duration_h`, `total_volumes`, `avg_volumes_per_run`, `avg_volumes_per_session`

Duration columns are in hours, volume columns count brain volumes (TRs). Cells are empty (NaN) when volume counts cannot be determined from sidecar JSON (e.g. `emotion-videos`).

## `fmri_stats.json`

BIDS-style JSON sidecar for `fmri_stats.tsv`. Describes each column with a `Description` and `Units` field.

## `figure_sessions.png`

Generated by `invoke run-notebooks` from `notebooks/figure_sessions.ipynb`.

Grid of bar charts: one summary panel (total sessions per subject across all datasets) and one panel per dataset showing the per-subject session count.

## `fmri_stats_per_subject.tsv`

Generated by `invoke run-fmri-per-subject-stats`. Long-format table with one row per (dataset, subject) pair.

Columns: `dataset`, `subject`, `total_runs`, `avg_runs_per_session`, `avg_session_duration_h`, `total_duration_h`, `total_volumes`, `avg_volumes_per_session`

Duration columns are in hours, volume columns count brain volumes (TRs). Cells are empty (NaN) when volume counts cannot be determined (e.g. `emotion-videos`, or subjects with no runs in a dataset).

## `cneuromod_tidy_per_subject.csv`, `cneuromod_tidy_total.csv`

Generated by `invoke run-cneuromod-tables` from the `stats` block of each
`source_data/cneuromod.all/<dataset>/dataset_info.yaml` (validated against
`cneuromod.all/docs/schema.json` first). Tidy long-format tables, one row per
(dataset, modality); `per_subject` holds per-subject values, `total` holds
totals across subjects. Task values exclude repetitions.

Columns: `dataset`, `group` (Brain / Tasks / Physiology), `group_color`, `modality`, `dotpath` (field path in `dataset_info.yaml`), `unit` (`h` hours, `#img` images, `#` count), `value` (empty when the dataset has no such data).

## `cneuromod_subjects.csv`

Generated by `invoke run-cneuromod-tables`. Per-dataset subject availability from the `subjects` list of each `dataset_info.yaml`.

Columns: `dataset`, `subject`, `status` (`available` / `partial` / `not_collected`), `note`

## `figure_cneuromod_comparison_per_subject.png`, `figure_cneuromod_comparison_total.png`

Generated by `invoke run-notebooks` from `notebooks/figure_cneuromod_comparison.ipynb`.

Bubble charts with one row per CNeuroMod dataset and one column per modality
(grouped into Brain, Tasks, Physiology), from the per-subject and total tidy
tables respectively. Bubble area grows with log(value); rows are sorted by brain-recording hours (descending).

## `PROVENANCE.json`

Written by `invoke run` (see `airoh.provenance.record_run`): the project's git
commit, the environment (Python, platform, declared package versions), the
input manifest it consumed, and a checksum of every output file. Changes on
every run — that churn is the record doing its job, not a bug.
